# Lesson 3 상세 진행안 — Vercel + Supabase 8시간 실습

팀별 프로젝트를 실제 배포하고 데이터 저장소를 연결해 동작하는 팀 사이트로 완성하는 회차의 강사용 진행안. 수강생 다수가 비개발자이므로 용어는 쉬운 말로 풀고, 각 교시는 "따라하면 되는" 단계로 구성한다.

## 진행 원칙

- 이론은 교시당 10~15분 이내로 짧게. 나머지는 팀별 실습.
- 모든 팀이 같은 속도로 가지 않는다 — 체크포인트(2교시 배포 주소, 5교시 데이터 표시)를 기준으로 뒤처진 팀을 따라잡힌다.
- 강사·외부 인원이 조를 나눠 순회 코칭. 막힌 화면은 강사 PC로 미러링해 함께 본다.
- 1·2회차에서 만든 팀 프로젝트를 그대로 이어서 쓴다. 새 프로젝트를 만들지 않는다.
- GitHub는 이미 사용 중이다 — 1회차에서 Git 가입·설치를 끝냈고, 2회차 코칭 동안 팀이 GitHub 저장소에 작업분을 올려가며 개발해왔다. 3회차는 "처음 올리기"가 아니라 그 저장소를 배포로 잇는 단계다.

## 사전 준비 (강사)

| 항목 | 내용 |
|------|------|
| 계정 | 팀별 GitHub 계정(1회차에 가입·설치 완료) + 작업분이 올라간 팀 저장소, Vercel 계정(GitHub 로그인), Supabase 계정 — 1교시 전 확인 |
| 저장소 점검 | 각 팀 GitHub 저장소에 최신 작업분이 push돼 있는지 1교시 전 확인. 로컬에만 있는 팀은 1교시에 push부터 |
| 샘플 | 배포까지 끝난 데모 레포 1개 (막힌 팀에게 정답 화면으로 제시) |
| 환경변수 표 | 팀이 채울 빈 표(키 이름 / 값 / 어디서 얻는지) 양식 |
| 네트워크 | 여의도 현장 와이파이 사전 점검 (Vercel·Supabase·GitHub 접속) |

## 1교시 — 프로젝트 정리 & 목표 합의

### 목표

오늘 배포할 범위를 팀별로 좁혀 합의하고, 화면에 보여줄 데이터 항목을 종이에 적게 한다.

### 진행

1. (이론 10분) "배포가 뭔가" — 내 컴퓨터에서만 보이던 사이트를 인터넷 주소로 누구나 볼 수 있게 올리는 것. Vercel = 사이트를 올리는 곳, Supabase = 데이터를 보관하는 곳.
2. 팀별로 1·2회차 프로젝트를 다시 연다. 무엇을 만드는 사이트였는지 한 문장으로 적는다.
3. "오늘 끝낼 범위" 합의 — 욕심내지 않고 핵심 화면 1~2개로 좁힌다.
4. 화면에 보여줄 데이터 항목을 적는다. 예: 공지사항이면 (제목 / 내용 / 작성일).

### 강사 포인트

- 범위가 너무 큰 팀은 "오늘은 이것만"으로 잘라준다. 나머지는 적어두고 나중에.
- 데이터 항목은 나중에 4교시 테이블 설계의 입력이 되므로 구체적으로 적게 한다.

### 산출물

- 팀별 "한 문장 목표" + "오늘 배포 범위" + "데이터 항목 목록".

## 2교시 — 일단 배포부터 성공

### 목표

완벽하지 않아도 좋으니, 팀 사이트를 인터넷 주소로 띄우는 데 성공한다. (체크포인트)

### 진행

1. 팀 GitHub 저장소를 연다 — 1·2회차에서 작업해 올려온 그 저장소. 최신 작업분이 push돼 있는지 확인하고, 로컬에만 남은 변경이 있으면 먼저 commit + push.
2. Vercel에 GitHub 계정으로 로그인 → "New Project" → 팀 저장소(이미 있는 것) 선택해 import.
3. 기본 설정 그대로 "Deploy" 클릭 → 잠시 기다리면 `https://팀이름.vercel.app` 주소가 나온다.
4. 그 주소를 휴대폰으로도 열어본다 — 내 컴퓨터가 아닌 곳에서도 보인다는 걸 체감.

### 강사 포인트

- 새 저장소를 만드는 게 아니라 **이미 있는 팀 저장소를 Vercel에 연결**하는 것임을 분명히 한다. (1회차에 git, 2회차에 GitHub 작업이 끝난 상태)
- push가 밀린 팀만 먼저 commit + push로 GitHub를 최신화한 뒤 import한다 — 막히면 화면 공유로 같이 한 번.
- 빌드 실패가 나도 당황 금지. 3교시에서 잡는다고 안내. 일단 주소가 나오는 것이 목표.
- 프레임워크 자동 감지(예: Next.js)가 안 되면 Vercel의 Framework Preset만 맞춰준다.

### 산출물 / 체크포인트

- 팀별 `*.vercel.app` 주소 확보. 화이트보드에 팀별 주소를 적어 공유.

## 3교시 — 배포 안정화 & 연결 준비

### 목표

배포 오류를 잡고, 환경변수 개념을 익히고, 코드를 고치면 자동으로 다시 배포되는 흐름을 확인한다. Supabase 연결 준비.

### 진행

1. 빌드 로그 읽는 법 — 빨간 글씨(에러)에서 파일명·줄 번호를 찾는다. 흔한 원인: 오타, 빠진 파일, 패키지 누락.
2. 환경변수가 뭔가 — 비밀번호·열쇠처럼 코드에 직접 쓰면 안 되는 값을 따로 보관하는 곳. Vercel Settings → Environment Variables.
3. 코드를 조금 고쳐 GitHub에 push → Vercel이 자동으로 다시 배포되는지 확인 (자동 재배포).
4. 다음 교시 대비 — Supabase 가입/로그인 확인, "키는 환경변수에 넣는다"는 원칙만 미리 안내.

### 강사 포인트

- 에러 메시지를 무서워하지 않게. "메시지를 읽으면 답이 있다"를 반복.
- 환경변수는 4·5교시의 핵심 준비물 — 여기서 자리를 잡아두면 5교시가 수월하다.

### 산출물

- 빌드 성공(초록) 상태의 안정 배포. 환경변수 입력 위치 숙지.

## 4교시 — 우리 데이터 저장소 설계

### 목표

Supabase 프로젝트를 만들고, 팀에 맞는 표(테이블)를 만든 뒤, 데이터를 직접 몇 줄 넣어본다.

### 진행

1. Supabase에서 New Project 생성 (이름·비밀번호·지역 선택). 비밀번호는 메모해 둔다.
2. Table Editor에서 표 만들기 — 1교시에 적은 데이터 항목이 그대로 열(column)이 된다. 예: `notices` 표에 `title`(글자), `content`(글자), `created_at`(날짜).
3. 표에 샘플 데이터 2~3줄을 손으로 직접 입력 → 데이터가 쌓이는 걸 눈으로 본다.
4. 열의 자료형(글자/숫자/날짜) 개념만 가볍게 — 깊이 들어가지 않는다.

### 강사 포인트

- "표(테이블) = 엑셀 시트 한 장"이라는 비유가 잘 통한다.
- 열 이름은 영어 소문자로 (예: `title`) — 5교시 코드 연결에서 그대로 쓰인다.
- 비밀번호·프로젝트 URL은 5교시에 필요하니 잃어버리지 않게 한다.

### 산출물

- 팀별 Supabase 프로젝트 + 테이블 1개 + 샘플 데이터 몇 줄.

## 5교시 — 사이트와 데이터 연결

### 목표

Supabase 키를 사이트에 연결해, 우리가 입력한 데이터가 실제 화면에 나오게 한다. (체크포인트)

### 진행

1. Supabase에서 연결 정보(Project URL + API Key) 복사.
2. 그 값을 Vercel 환경변수에 넣는다 (3교시에 잡아둔 자리). 코드에 직접 쓰지 않는다.
3. 사이트 코드에서 Supabase를 불러와 테이블 데이터를 화면에 표시 — 강사 제공 스니펫을 붙여넣고 표 이름·열 이름만 팀 것으로 바꾼다.
4. 배포 후 사이트를 열어 4교시에 넣은 데이터가 화면에 보이는지 확인.

### 강사 포인트

- 가장 막히기 쉬운 교시 — 키를 잘못 넣거나 표 이름 오타가 흔하다. 체크리스트로 하나씩 짚는다.
- 화면에 안 나오면: (1) 환경변수 철자 (2) 표/열 이름 일치 (3) 공개 권한(RLS) 순서로 점검.
- 데이터가 한 줄이라도 화면에 뜨면 크게 격려 — 성취감이 6교시 동력.

### 산출물 / 체크포인트

- 팀 사이트 화면에 Supabase 데이터가 표시됨.

## 6교시 — 핵심 기능 붙이기

### 목표

팀 프로젝트 성격에 맞는 핵심 기능을 1개 이상 붙인다 (등록·조회·신청·로그인 등).

### 진행

1. 팀별로 "가장 중요한 기능 1개"를 고른다. 예: 글 등록, 목록 조회, 신청 접수, 로그인.
2. 등록(쓰기) 기능 — 화면 입력값을 Supabase 표에 새 줄로 저장.
3. 조회(읽기) 기능 — 저장된 데이터를 목록/상세로 보여주기.
4. 여력 있는 팀은 검색·필터·간단 로그인까지 확장.

### 강사 포인트

- 한 팀당 기능 1개를 끝까지 동작시키는 것이 여러 개 절반보다 낫다.
- 비개발자 팀은 강사·외부 인원이 Claude로 코드 생성을 함께 돕되, 무엇을 하는 코드인지 한 줄로 설명해준다.
- 진도 차이가 가장 벌어지는 교시 — 빠른 팀에는 확장 과제, 느린 팀에는 등록·조회까지만.

### 산출물

- 팀별 핵심 기능 1개 이상 동작.

## 7교시 — 점검 & 완성

### 목표

최종 동작을 확인하고, 자주 나는 오류를 해결하고, 막힌 팀을 따라잡혀 모든 팀이 발표 가능한 상태로 만든다.

### 진행

1. 팀별 체크리스트 점검 — 배포됨 / 데이터 표시됨 / 핵심 기능 동작함.
2. 흔한 오류 일괄 해결 — 환경변수 누락, 권한(RLS), 모바일 화면 깨짐 등.
3. 막힌 팀 집중 코칭 — 강사·외부 인원이 붙어 체크포인트까지 끌어올린다.
4. 발표용으로 보여줄 화면·순서를 팀별로 정리.

### 강사 포인트

- "완벽"이 아니라 "발표 가능"이 목표. 미완 기능은 솔직히 보여줘도 괜찮다고 안내.
- 공통적으로 막히는 지점은 전체 화면 공유로 한 번에 푼다.

### 산출물

- 모든 팀이 발표 가능한 완성 상태.

## 8교시 — 팀별 발표 & 공유

### 목표

팀별로 사이트를 시연하고 결과를 공유한 뒤, Q&A로 마무리한다.

### 진행

1. 팀별 5~7분 시연 — 사이트 주소 열기 → 핵심 기능 1개 실제 동작 시연 → 배운 점 한마디.
2. 팀 간 상호 피드백 (좋았던 점 1, 궁금한 점 1).
3. 마무리 Q&A — 배포·데이터 관련 자주 나온 질문 정리.
4. 사후 A/S 안내 — 1~2개월 뒤(약 9월경) 온/오프라인 Q&A 예정 ([README](../../README.md) 사후 A/S 참조).

### 강사 포인트

- 코드 완성도보다 "직접 배포해 인터넷에 올렸다"는 경험을 축하하는 자리로.
- 각 팀 사이트 주소를 공유 문서에 모아 사후 A/S 때 다시 참고한다.

### 산출물

- 팀별 시연 완료 + 사이트 주소 공유 목록 + Q&A 정리.

## 자주 나는 오류 모음 (강사 참고)

| 증상 | 흔한 원인 | 해결 |
|------|-----------|------|
| 배포는 됐는데 흰 화면 | 빌드는 통과했으나 런타임 오류 | Vercel 함수/런타임 로그 확인 |
| 데이터가 화면에 안 나옴 | 환경변수 철자, 표/열 이름 불일치 | 키·이름 1:1 대조 |
| `permission denied` 류 | Supabase 행 보안(RLS) 미설정 | 조회용 정책 추가 또는 데모는 공개 정책 |
| 코드 고쳤는데 사이트 그대로 | push 누락 또는 캐시 | GitHub 반영 확인 → 재배포 |
| 로컬은 되는데 배포만 실패 | 환경변수가 Vercel에만 없음 | Vercel Settings에 동일 값 추가 |
