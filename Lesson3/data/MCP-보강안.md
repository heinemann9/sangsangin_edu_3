# Lesson 3 부족분 진단 & MCP 중심 강의 설계안

2회차 이론 자료(AXLab `Docs/Lesson2/data/claude-agentic-ai-2026-08.md/.html`, 7파트 41슬라이드)를 기준으로 본 저장소 Lesson 3의 빠진 부분을 짚고, **MCP를 3회차의 축으로 삼는** 강의 설계를 정리한다.

---

## 1. 두 자료가 지금 어떻게 어긋나 있나

| | Lesson 2 (2회차 이론) | Lesson 3 (3회차, 본 저장소) |
|---|---|---|
| 성격 | 개념·프레임워크 중심 발표 | 손으로 따라하는 배포·데이터 실습 |
| MCP 취급 | **개념 슬라이드 1장** — "도구 수만큼 연동(M×N) → MCP 하나면 충분(M+N)", 실습은 Context7 | **실무 도구로 이미 씀** — Vercel MCP·Supabase MCP 따라하기 3종 + 스크린샷 24장 |
| 보안 | Prompt Injection / Tool Poisoning을 "미해결 과제"로 경고 | 각 따라하기 문서 끝의 "안전하게 쓰기" 절에만 존재 |
| 세션·운용 | 모드 전환, `/clear`, Skill·Hook, Verify 루프 | 언급 없음 |

**핵심 어긋남**: Lesson 2는 MCP를 *개념*으로 소개하고 끝나고, Lesson 3은 MCP를 *이미 쓰는 도구*로 전제한다. 그 사이를 잇는 "연결하고 → 권한을 주고 → 검증하는" 구간이 어느 회차에도 편성돼 있지 않다. 일정표상 MCP 관련 시간은 1회차 17:00–18:00 "MCP 하나 연결(`/mcp`)" 한 칸이 전부다.

## 2. Lesson 3에서 부족한 것 (8건)

우선순위 순. 앞의 4건은 3회차 진행에 직접 영향을 준다.

### G1. 진행안이 8교시 균등 배분 + 웹 클릭 기준이다 [높음]

**구조 문제** — `data/Curriculum.md`는 8교시를 균등하게 나누고 매 교시 팀별 실습을 굴린다. 그러면 오전에도 팀마다 다른 화면을 보게 되어 **강사 시연이 성립하지 않는다**. 2회차에서 설계·개발 코칭이 이미 끝났으므로 3회차의 본론은 새 도구 2개를 익히는 것이고, 도구 학습은 전원 같은 화면이 압도적으로 유리하다. → 3-2에서 오전 공통 / 오후 개별로 재편.

**서술 문제** — 진행안은 전부 웹 UI 클릭 절차로 쓰여 있다. MCP 버전 따라하기 3종은 그 뒤에 추가됐는데 진행안에 반영되지 않았다.

- 2교시 진행: "Vercel에 로그인 → New Project → import" (웹만)
- 5교시 진행: "Supabase에서 Project URL + API Key 복사 → Vercel 환경변수에 넣는다" (웹만)
- 사전 준비 표에 MCP 연결·`npx vercel login` 항목 없음

→ 강사가 MCP 버전으로 진행하려면 문서 두 개를 머릿속으로 합쳐야 한다.

### G2. MCP 연결 자체를 가르치는 시간이 없다 [높음]

`Vercel-배포-따라하기-MCP.md` 4단계와 `Supabase-따라하기-MCP.md` 0단계가 요구하는 선행 작업:

```
claude mcp add --transport http --scope user vercel https://mcp.vercel.com
claude mcp add --transport http supabase https://mcp.supabase.com/mcp
/mcp → 서버 선택 → Authenticate → 브라우저 OAuth(팀·프로젝트 선택 → Allow) → Connected
npx vercel login          # 환경변수 등록은 MCP가 아니라 CLI 경유 (문서 강사 메모에 명시)
```

Claude Code 재시작(`claude --continue`), 브라우저 왕복, 팀/프로젝트 선택, 조직 권한 승인까지 **비개발자 기준 1인 10~15분**이 드는 절차다. 8명이면 편차까지 감안해 최소 40~50분. 현재 8교시 어디에도 이 슬롯이 없다.

### G3. 웹 트랙 / MCP 트랙 운영 기준이 없다 [높음]

따라하기 문서가 웹 3종·MCP 3종으로 쌍을 이루는데, **어느 팀에 무엇을 시킬지 판단 기준이 문서화돼 있지 않다.** 대상은 8명 2조이고 진도 편차가 큰 구성이다(Curriculum.md 진행 원칙: "모든 팀이 같은 속도로 가지 않는다"). 현장에서 강사마다 다르게 운영되면 체크포인트 시각이 어긋난다.

### G4. MCP 특유의 실패가 오류 모음에 없다 [높음]

`Curriculum.md` "자주 나는 오류 모음" 5건은 전부 웹·빌드 기준이다. MCP로 진행하면 나오는 실패는 성격이 다르다.

| MCP 실패 | 증상 | 원인 |
|---|---|---|
| 인증 안 됨 | Claude가 "권한이 없다"고 답함 | `/mcp`에 Connected 아님 / OAuth 중단 |
| 엉뚱한 프로젝트 조작 | 다른 팀 프로젝트가 바뀜 | OAuth 때 팀·프로젝트를 잘못 선택 |
| 환경변수 등록 실패 | Claude가 CLI 오류를 뱉음 | `npx vercel login` 미실행 (G2) |
| 서버 목록에 안 뜸 | `/mcp`에 항목 없음 | `claude mcp add` 후 재시작 안 함 |
| 조용한 실수 | "했습니다"라는데 실제로는 안 됨 | 결과 확인 없이 넘어감 → **Verify 필요** |

### G5. 보안이 실습에 붙어 있지 않다 [중간]

Lesson 2는 Tool Poisoning을 "Anthropic도 미해결"로 경고하고 끝난다. 그런데 3회차에서 수강생은 MCP에 **실제 DB 쓰기 권한과 배포 권한**을 준다. 개념 경고와 실제 권한 부여 사이가 비어 있다. 각 따라하기 문서의 "안전하게 쓰기" 절은 좋지만, 교시 진행안에 게이트로 박혀 있지 않아 건너뛰기 쉽다.

### G6. 2회차에서 배운 운용 기법이 3회차에서 끊긴다 [중간]

Lesson 2가 가르친 `CLAUDE.md`, Skill, `/clear`, 모드 전환(Shift+Tab), Verify 루프가 Lesson 3 문서에 한 번도 나오지 않는다. 8시간 실습은 컨텍스트가 가장 잘 뭉개지는 구간인데(Lesson 2 ch2 "Context Rot") 대응 지침이 없다.

### G7. 로그인·글쓰기 문서가 교시에 매핑돼 있지 않다 [중간]

`Supabase-로그인-글쓰기-MCP.md`(GitHub OAuth 로그인 + 본인 글만 보이게 하는 RLS)는 6교시 "핵심 기능 붙이기"에 정확히 대응하는데, `Summary.md`·`Curriculum.md` 어디에도 링크가 없다.

### G8. 문서 색인이 낡았다 [낮음]

`Summary.md`가 링크하는 문서는 `Curriculum.md`와 **Vercel 웹 버전 1개뿐**이다. 실제 `data/`에는 문서 9개 + 스크린샷 3세트(mcp 24장 / supabase 26장 / vercel 9장)가 있다. 처음 여는 사람은 MCP 문서의 존재를 모른다.

## 3. MCP를 축으로 한 강의 설계

### 3-1. 한 줄 메시지

> **"클릭으로 하던 일을 말로 시킨다. 대신 권한을 주는 것이므로, 시키고 → 확인한다."**

MCP를 "편한 기능"으로 팔지 않는다. **권한을 위임하는 행위**로 가르치고, 그래서 Verify가 따라붙는다는 것을 8시간 내내 반복한다. 이것이 Lesson 2의 Tool Poisoning 경고와 Verify 루프를 3회차 실습으로 착지시키는 방법이다.

### 3-2. 하루 구조 — 오전 공통 따라하기 / 오후 개별 코칭 (G1·G2·G3 해소)

기존 8교시 균등 배분을 **오전(3h) 공통 · 오후(5h) 개별** 2블록으로 재편한다.

| | 오전 (09:00–12:00) | 오후 (13:00–18:00) |
|---|---|---|
| 대상 | 전원 같은 화면 | 팀별로 다른 프로젝트 |
| 재료 | **강사 제공 공통 샘플 레포** | 1·2회차에서 만든 팀 프로젝트 |
| 방식 | 강사가 앞에서 한 단계씩 시연 → 따라하기 | 강사 2인이 조를 나눠 순회 코칭 |
| 목표 | Vercel·Supabase를 한 번 완주 | 그 절차를 내 프로젝트에 적용 |

**근거 3가지**

1. **2회차에서 설계·개발 코칭이 이미 끝났다.** 3회차의 본론은 팀 프로젝트를 더 만드는 것이 아니라 **새 도구 2개(Vercel·Supabase)를 익히는 것**이다. 도구 학습은 전원 같은 화면이 압도적으로 효율적이다.
2. **오전에 팀마다 다른 걸 하면 시연이 불가능하다.** 강사 2인이 8명에게 쪼개지면 앞에서 한 번에 보여주는 것이 성립하지 않는다.
3. **오전에 전원이 한 번 완주해두면 오후에 되짚을 기준점이 생긴다.** 막혔을 때 "오전에 했던 그 단계"로 되돌릴 수 있고, 이것이 진도 편차를 흡수하는 가장 싼 방법이다. 진도 편차는 오후에만 발생하므로 코칭 인력을 오후 5시간에 몰아 쓴다.

> **기존 진행 원칙과의 충돌** — `Curriculum.md` 진행 원칙에 "새 프로젝트를 만들지 않는다"가 있다. 오전에 공통 샘플을 쓰는 것은 이와 어긋나 보이지만, 샘플은 **버리는 연습 재료**이고 팀 프로젝트는 오후에만 건드리므로 취지(팀 결과물을 흩뜨리지 않는다)는 유지된다. 이 판단을 뒤집는다면 오전을 팀 프로젝트로 진행하되 시연 없이 순회 코칭만 하는 형태가 되고, 오후와의 구분이 사라진다.

### 3-3. 시간 배분

| 시간 | 구분 | 내용 |
|---|---|---|
| 09:00–09:30 | 이론 | 오늘의 흐름 · 배포란 무엇인가(Vercel) · 데이터 저장소란 무엇인가(Supabase) |
| 09:30–10:00 | MCP 연결 | `claude mcp add` 2개 → 재시작 → `/mcp` 인증 → `npx vercel login` |
| 10:00–11:00 | 따라하기 ① | Vercel 배포 — 저장소 연결 → Deploy → 주소 확인 → 자동 재배포 · 빌드 로그 읽는 법 · 환경변수 개념 |
| 11:00–12:00 | 따라하기 ② | Supabase — 표 만들기 → 데이터 입력 → RLS → 환경변수 → **화면에 데이터 표시까지** (오전 체크포인트) |
| 13:00–13:30 | 범위 합의 | 팀 프로젝트 열고 한 문장 목표 + 오늘 배포 범위 + 데이터 항목 적기 |
| 13:30–15:00 | 코칭 ① | 내 프로젝트 배포 (체크포인트: 팀 사이트 주소) |
| 15:00–16:30 | 코칭 ② | 내 데이터 연결 (체크포인트: 데이터 화면 표시) |
| 16:30–17:15 | 코칭 ③ | 핵심 기능 1개 + 확인 습관 5분 |
| 17:15–18:00 | 발표 | 팀별 시연 · Q&A · 사후 A/S 안내 |

문서 매핑: 오전 ① = `Vercel-배포-따라하기(-MCP).md`, 오전 ② = `Supabase-따라하기(-MCP).md`, 오후 코칭 ③ = `Supabase-로그인-글쓰기-MCP.md` (G7 해소).

### 3-4. 웹 화면 / MCP 병행 기준 (G3 해소)

전원 MCP로 밀지 않는다. **오전 시연은 두 화면을 나란히 보여주고, 오후에는 팀 상태에 따라 갈린다.**

| | 웹 화면 | MCP |
|---|---|---|
| 쓰는 곳 | 처음 보는 개념 — 무엇이 어디 있는지 눈으로 | 반복·수정 — 클릭 20번이 문장 1줄로 |
| 오전 | 기준 화면 (전원 동일) | 같은 작업을 MCP로 한 번 더 보여줌 |
| 오후 | 연결 실패자·막힌 팀의 안전망 | 배포 오류 잡기·환경변수 등록의 주력 |
| 문서 | `Vercel-배포-따라하기.md` · `Supabase-따라하기.md` | `*-MCP.md` 3종 |

**MCP 주력 전환 조건** — 다음 3개를 만족한 팀만:

1. `/mcp`에 `vercel`·`supabase`가 **Connected**
2. `npx vercel login` 완료
3. 오전 따라하기 완주

만족 못 하면 웹 화면으로 계속 간다. **MCP 때문에 체크포인트를 놓치는 팀이 생기면 안 된다** — MCP는 가속 장치이지 통과 조건이 아니다.

### 3-5. MCP 이론은 3번, 각 5분 (몰아서 하지 않는다)

| 시점 | 내용 | 붙는 실습 |
|---|---|---|
| 09:30 | **통로** — 클릭 대신 말로 시키려면 통로가 필요하다. `/mcp`가 그 통로 목록 | 그 자리에서 `claude mcp add` |
| 10:00 따라하기 ① 중 | **권한** — 통로를 여는 건 "내 계정으로 대신 해도 좋다"는 위임. OAuth에서 팀·프로젝트를 고르는 화면이 권한 범위를 정하는 순간 | Vercel OAuth 화면을 띄워놓고 설명 |
| 16:30 코칭 ③ 뒤 | **검증** — 위임했으면 확인해야 한다. Claude의 "했습니다"는 증거가 아니다 | 3-6 확인 습관 |

Lesson 2의 M×N → M+N 그림은 09:30에 30초만 재인용한다. 이론 반복이 아니라 **"그래서 지금 이걸 여는 것"** 연결에만 쓴다.

### 3-6. 확인 습관 — 코칭 ③ 뒤 5분 (G4·G5 해소)

MCP를 가르치면서 이것을 빼면 안 되는 부분. 팀별로 직접 확인:

1. **결과를 눈으로** — Claude가 "환경변수 등록했습니다"라고 하면, Vercel 웹 화면을 열어 실제로 있는지 본다. (한 번은 반드시 시킨다)
2. **권한 범위 확인** — `/mcp`에서 연결된 서버·계정을 보고, "지금 이 통로로 무엇까지 할 수 있나"를 팀이 말로 답한다.
3. **잠금 확인** — `Supabase-따라하기-MCP.md` "잠겨 있다는 걸 눈으로 확인해보기" 절대로 RLS가 실제로 막는지 확인.
4. **끄는 법** — 교육 끝나고 안 쓸 통로는 닫는다. `claude mcp remove` / OAuth 앱 해제.
5. **키는 어디에** — 키를 코드나 채팅에 붙여넣지 않는다. 환경변수에만. (Lesson 2 Tool Poisoning의 실무 번역)

### 3-7. Lesson 2 연결 (G6 해소)

3회차에 최소 셋만 이어 쓴다. 새로 가르치지 않고 "2회차에 배운 그것"으로 호출한다.

- **`CLAUDE.md`** — 13:00 범위 합의 때 팀 프로젝트 규칙 5줄(표 이름·열 이름·쓰지 말 것)을 적어두면 오후 코칭의 코드 생성 품질이 달라진다.
- **`/clear`** — 오전 따라하기가 끝나고 오후 팀 프로젝트로 넘어갈 때 반드시. 안 끊으면 오후에 Claude가 오전 샘플과 팀 프로젝트를 섞는다.
- **Verify** — 3-6이 곧 이것. "완전한 자동화의 조건"(Lesson 2 ch5)의 실습판.
