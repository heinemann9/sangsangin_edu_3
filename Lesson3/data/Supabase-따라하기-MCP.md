# Supabase 따라하기 — MCP 버전 (비개발자용)

[Supabase 따라하기](Supabase-따라하기.md)와 **목표가 똑같은 문서**입니다. 다른 점은 **웹 화면에서 버튼을 누르는 대신, Claude Code 창에 말로 요청**한다는 것입니다.

- **웹 버전**: Supabase 사이트에 들어가 표를 만들고, 데이터를 손으로 입력하고, 키를 복사해 붙여넣습니다.
- **MCP 버전(이 문서)**: "공지사항 표 만들어줘"라고 말하면 Claude가 대신 만듭니다.

> **MCP가 뭔가요?** Claude Code가 Supabase·Vercel 같은 서비스에 **직접 연결되는 통로**입니다. 통로가 열리면 여러분이 대신 클릭하지 않아도 Claude가 그 서비스를 조작할 수 있습니다. 1·2회차에서 쓰던 **"저장해줘"·"최신으로 맞춰줘"와 같은 방식** — 말로 요청하면 Claude가 처리하는 것 — 이 Supabase까지 넓어진 것입니다.

> **어느 문서를 봐야 하나요?** 강사 안내를 따르세요. 둘 다 결과는 같습니다. 웹 버전은 "화면을 눈으로 익히는" 장점이 있고, MCP 버전은 "빠르고 오타가 안 나는" 장점이 있습니다.

---

## 준비물

- **Claude Code**가 설치되어 실행되는 상태 (1회차에서 준비 완료)
- **팀 프로젝트 폴더**에서 Claude Code를 열어둔 상태
- **Supabase 계정** (GitHub으로 가입 가능)
- [Vercel 배포 따라하기](Vercel-배포-따라하기.md) 완료 — 사이트가 `주소.vercel.app`으로 떠 있어야 합니다

전체 흐름은 이렇게 5단계입니다. 웹 버전 7단계가 5단계로 줄었습니다.

```
0. 통로 열기(MCP 연결) → 1. 표 만들기 → 2. 데이터 넣기
   → 3. 읽기 공개 정책 → 4. 사이트에 연결 → 5. 화면 확인
```

---

## 0단계 — 통로 열기 (MCP 연결)

한 번만 하면 됩니다. 다음에는 이 단계를 건너뜁니다.

1. Claude Code 창에 아래를 **그대로** 입력합니다.

```
/mcp
```

2. 목록에서 **Supabase**를 고르고 Enter를 누릅니다.
3. 브라우저가 열리면 Supabase 계정으로 로그인하고 **허용(Authorize)**을 누릅니다.
4. 터미널로 돌아와 `Connected`라고 나오면 성공입니다.

> **목록에 Supabase가 없으면** 아직 등록이 안 된 것입니다. 아래를 입력한 뒤 Claude Code를 **종료하고 `claude --continue`로 다시 시작**하면 목록에 나타납니다. (그냥 `claude`로 시작하면 대화 내용이 사라집니다.)
>
> ```
> claude mcp add --transport http supabase https://mcp.supabase.com/mcp
> ```

> **강사 포인트**: 이 통로는 여러분 Supabase 계정 **전체**에 연결됩니다. 다른 팀 프로젝트를 실수로 건드리지 않도록, 강사가 팀별로 범위를 좁혀 등록해 줄 수 있습니다. 아래 "안전하게 쓰기" 참고.

---

## 1단계 — 표 만들기

**표(테이블)** = 엑셀 시트 한 장입니다. 1교시에 종이에 적은 데이터 항목이 그대로 **열(column)**이 됩니다.

Claude Code 창에 **우리 팀 내용으로 바꿔서** 이렇게 말합니다.

```
supabase에 공지사항 표 만들어줘.
표 이름은 notices,
제목(title)은 글자, 내용(content)은 글자,
작성일은 자동으로 들어가게 해줘.
```

Claude가 표를 만들고 이렇게 답합니다.

```
notices 표를 만들었습니다.
  id          자동 번호
  title       제목 (글자)
  content     내용 (글자)
  created_at  작성일 (자동)
행 보안(RLS)을 켜 두었습니다.
```

이게 끝입니다. 웹 버전의 2단계(Table Editor에서 열 하나하나 추가) 전체가 이 한 줄로 대체됩니다.

> **바꿀 것은 이름뿐입니다.** 공지사항이 아니라 "맛집 목록"이면 `notices` 대신 `places`, `title`·`content` 대신 `name`·`address`처럼 우리 팀 항목을 말하면 됩니다. **영어 소문자**로 지어달라고 하세요 — 6단계 코드에서 이 이름을 그대로 씁니다.

> **표가 제대로 만들어졌는지 확인**하려면 `우리 표 구조 보여줘`라고 말하면 됩니다.

---

## 2단계 — 데이터 몇 줄 넣기

표가 비어 있으면 화면에도 아무것도 안 나옵니다. 2~3줄 넣어봅니다.

```
notices에 공지 3개 넣어줘.
첫 공지 / 상상인 교육 3회차에 오신 것을 환영합니다
둘째 공지 / 오늘은 Vercel과 Supabase를 연결합니다
셋째 공지 / 팀별 발표는 8교시에 진행합니다
```

Claude가 넣고 결과를 보여줍니다.

```
3건 넣었습니다.
  1. 첫 공지
  2. 둘째 공지
  3. 셋째 공지
```

웹 버전 3단계(Insert row를 세 번 반복)가 한 번에 끝납니다.

---

## 3단계 — 읽기 공개 정책 (RLS)

여기가 **가장 중요한 단계**입니다. 지금 상태로는 데이터가 표 안에 있어도 **사이트 화면에는 안 나옵니다.**

Supabase는 표를 만들 때 **행 보안(RLS)**을 켜 두는데, 이건 "바깥에서 함부로 읽지 못하게" 잠가두는 장치입니다. 잠금을 풀지 않으면 우리 사이트도 못 읽습니다.

```
notices를 누구나 읽을 수 있게 공개 정책 걸어줘.
쓰기는 막아둬.
```

```
읽기 공개 정책을 추가했습니다.
이제 사이트에서 목록을 불러올 수 있습니다.
쓰기는 여전히 막혀 있습니다.
```

### 잠겨 있다는 걸 눈으로 확인해보기 (선택)

궁금하면 정책을 걸기 **전에** 이렇게 물어보세요.

```
지금 바깥에서 notices를 읽으면 어떻게 되는지 확인해줘
```

Claude가 실제로 바깥에서 요청을 보내 결과를 보여줍니다. 표에 데이터 3줄이 **분명히 있는데도** 이렇게 나옵니다.

```
읽기 결과: []   (빈 목록)
```

에러가 아니라 **빈 목록**이 온다는 게 핵심입니다. 그래서 "왜 화면에 아무것도 안 나오지?" 하고 한참 헤매게 됩니다. 정책을 걸고 다시 확인하면 3줄이 나옵니다.

> **이건 데모라서 공개로 여는 설정입니다.** 비밀번호·개인정보 같은 민감한 데이터는 이렇게 열지 않습니다. 실제 서비스에서는 "로그인한 사람만" 같은 조건을 붙여 좁힙니다.

---

## 4단계 — 사이트에 연결 (주소·열쇠 + 재배포)

사이트가 이 표를 읽으려면 **주소(URL)**와 **열쇠(API Key)**가 필요합니다. 웹 버전은 이 두 값을 눈으로 찾아 복사해 Vercel에 붙여넣는데(4·5단계), **여기가 가장 오타가 많이 나는 구간**입니다.

MCP 버전은 한 줄입니다.

```
우리 supabase 주소랑 열쇠를 vercel 환경변수에 넣고 다시 배포해줘
```

Claude가 순서대로 처리하고 보고합니다.

```
Supabase에서 값을 가져왔습니다.
Vercel에 등록했습니다.
  NEXT_PUBLIC_SUPABASE_URL
  NEXT_PUBLIC_SUPABASE_ANON_KEY
재배포를 시작했습니다. 1~2분 걸립니다.
```

사람이 값을 옮기지 않으므로 **철자 오타가 구조적으로 발생하지 않습니다.** 웹 버전 "자주 막히는 곳" 1·4·5번(환경변수 철자, Vercel에만 없음, 재배포 안 함)이 여기서 사라집니다.

> **열쇠는 두 종류가 있습니다.** `anon`(익명용, 공개해도 되는 키)과 `service_role`(관리자용 비밀 키)입니다. **anon만** 사이트에 넣습니다. Claude에게 맡기면 알아서 anon을 씁니다. 직접 다룰 때는 이름에 `anon`이 있는 것만 쓰세요.

> **코드는 어떻게 되나요?** 화면에 목록을 보여주는 코드가 아직 없으면 `우리 사이트에 공지 목록 보여주는 화면 만들어줘`라고 말하면 됩니다. 이 부분은 웹 버전 6단계와 같고, MCP와 무관하게 Claude가 원래 해주던 일입니다.

---

## 5단계 — 화면에서 확인

1. 1~2분 기다립니다.
2. 우리 사이트 주소를 새로고침합니다.
3. 2단계에서 넣은 공지가 **화면에 목록으로** 보이면 성공입니다.

배포가 끝났는지 궁금하면 이렇게 물어보세요.

```
배포 다 됐어?
```

여기까지 왔으면 오늘의 핵심 체크포인트(5교시)를 통과한 것입니다. 우리가 만든 표의 데이터가 인터넷 사이트에 실제로 나온 것입니다.

---

## 자주 막히는 곳 (체크리스트)

MCP 버전에서는 막히는 지점이 웹 버전보다 적습니다. 화면에 데이터가 안 나오면 **아래 순서대로** 확인하세요.

| 순서 | 증상 | 이렇게 말하세요 |
|------|------|-----------------|
| 1 | 화면에 아무것도 안 나옴 | `우리 표에 데이터 몇 개 있어?` — 0건이면 2단계로 |
| 2 | 데이터는 있는데 안 보임 | `notices 읽기 정책 확인해줘` — 3단계 누락이 가장 흔함 |
| 3 | 표·열 이름 불일치 | `화면 코드랑 표 이름이 맞는지 확인해줘` |
| 4 | 값을 넣었는데 그대로 | `다시 배포해줘` |
| 5 | 배포가 실패함 | `배포 왜 실패했어?` — Claude가 빌드 기록을 읽고 원인을 알려줍니다 |
| 6 | 뭐가 문제인지 모르겠음 | `우리 supabase 설정에 문제 있는지 점검해줘` — 빠진 정책 등을 찾아줍니다 |

5번이 MCP 버전의 큰 장점입니다. 웹 버전에서는 Vercel 대시보드에서 로그를 직접 찾아 읽어야 하는데, 여기서는 Claude가 읽고 쉬운 말로 설명해 줍니다.

## 안전하게 쓰기 (꼭 읽어주세요)

MCP 통로는 편한 만큼 **권한이 셉니다.** Claude가 표를 만들 수 있다는 건, **지울 수도 있다**는 뜻입니다.

### 해야 할 것

- **"지워줘"·"초기화해줘" 같은 말은 신중하게.** 무엇이 지워지는지 확인하고 답하세요.
- **다른 팀 프로젝트가 같은 계정에 있으면 강사에게 범위 제한을 요청**하세요. 프로젝트 하나에만 연결되도록 좁힐 수 있습니다.

  ```
  claude mcp add --transport http supabase-우리팀 \
    "https://mcp.supabase.com/mcp?project_ref=우리프로젝트ID&read_only=false"
  ```

- **조회만 할 때는 읽기 전용**으로 열어두면 사고가 원천 차단됩니다. 위 주소 끝의 `read_only=false`를 `read_only=true`로 바꾸면 됩니다. 단 이 상태에서는 표 만들기·정책 걸기가 안 됩니다.

### 하지 말아야 할 것

- **`service_role` 키를 사이트·코드·채팅에 넣지 않기.** 관리자 비밀 키이며, 유출되면 RLS 정책이 전부 무의미해집니다.
- **남의 팀 프로젝트에 연결된 상태로 작업하지 않기.**

## 웹 버전과 나란히 보기

| 웹 버전 단계 | MCP 버전 | 달라지는 점 |
|---|---|---|
| 1단계 프로젝트 만들기 | (강사 사전 준비) | 강사가 팀별로 미리 만들어 둡니다 |
| 2단계 표 만들기 | 1단계 | 열을 하나하나 추가 → 한 문장 |
| 3단계 데이터 넣기 | 2단계 | Insert row 반복 → 한 번에 |
| RLS 공개 정책 | 3단계 | 메뉴를 찾아 들어감 → 한 문장 |
| 4단계 연결 정보 복사 | 4단계에 흡수 | 눈으로 찾아 복사 → 자동 |
| 5단계 환경변수 입력 | 4단계에 흡수 | 손으로 붙여넣기(오타 빈발) → 자동 |
| 6단계 코드 붙여넣기 | (그대로) | 원래 Claude가 하던 일 |
| 7단계 재배포·확인 | 4·5단계 | 대시보드 클릭 → 한 문장 |

## 강사 메모

- 본 문서는 [Supabase 따라하기](Supabase-따라하기.md)(웹 클릭 버전)의 **대체가 아니라 병행**입니다. [Curriculum.md](Curriculum.md) 4·5교시에 동일하게 대응합니다.
- **핵심 체크포인트는 동일하게 5단계(화면 표시)** — 웹 버전 7단계와 같습니다.
- **웹 버전을 먼저 한 번 보여주고 MCP 버전으로 실습**하는 순서를 권합니다. Supabase 화면을 한 번도 안 보고 넘어가면 "무엇이 어디에 있는지" 감이 안 잡혀, 나중에 대시보드에서 확인할 때 막힙니다.
- **1단계(프로젝트 생성)는 강사 사전 준비로 빼는 것을 권합니다.** MCP로 팀별 프로젝트·표·정책을 일괄 생성해두면 [Curriculum.md](Curriculum.md) "사전 준비" 표의 항목 대부분이 반자동화됩니다. 수강생은 4~5단계(연결·확인)에 집중.
- **수강생 계정에 계정 전체 권한으로 붙이지 않도록** 주의. `project_ref`로 팀별 스코프하거나, 강사 PC에서만 전체 권한을 씁니다. 8개 팀이 한 조직에 있으면 오타 한 번에 남의 팀 표가 날아갈 수 있습니다.
- **GitHub 로그인·글쓰기(6교시)**는 [로그인·글쓰기 붙이기 (MCP 버전)](Supabase-로그인-글쓰기-MCP.md)으로 분리했습니다. GitHub OAuth App 생성만은 자동화가 불가능(GitHub이 API를 제공하지 않음)하므로 강사가 미리 만들어 두는 편이 낫습니다.
- **환경변수 등록은 Vercel MCP 기능이 아니라 CLI(`vercel env add`) 경유**입니다. Claude가 알아서 처리하지만, 수강생 PC에 `vercel login`이 되어 있어야 합니다. 1교시에 함께 해두면 4단계가 매끄럽습니다.
