왜 오전 공통 / 오후 개별인가

  • 2회차에서 설계·개발 코칭이 끝났으므로, 3회차는 새 도구 2개(Vercel·Supabase)를 익히는 것이 본론
  • 오전에 팀마다 다른 걸 하면 강사 2인이 8명에게 쪼개져 시연이 불가능하다 — 같은 화면이어야 앞에서 한 번에 보여줄 수 있다
  • 오전에 전원이 한 번 완주해두면, 오후에 막혔을 때 "오전에 했던 그 단계"라는 공통 기준점이 생긴다
  • 진도 편차는 오후에만 발생 → 코칭 인력을 오후에 몰아 쓴다(5시간)

운영 규칙

  • 오전 따라하기는 강사 제공 공통 샘플로. 팀 프로젝트는 오후에만 건드린다
  • MCP는 가속 장치이지 통과 조건이 아니다 — 연결 실패자는 웹 화면으로 계속 간다
  • 오후 체크포인트가 절대 기준. 기능 욕심보다 체크포인트 통과 우선
  • 공통으로 막히는 지점은 전체 화면 공유로 한 번에 푼다

자주 나는 오류 — 배포·데이터

  • 배포는 됐는데 흰 화면 → 런타임 로그 확인
  • 데이터가 화면에 안 나옴 → 환경변수 철자, 표·열 이름 대조
  • permission denied → Supabase RLS 정책
  • 고쳤는데 사이트 그대로 → push 누락 또는 캐시
  • 로컬은 되는데 배포만 실패 → Vercel에 환경변수 누락

자주 나는 오류 — MCP

  • "권한이 없다"고 답함 → /mcp가 Connected 아님, OAuth 중단
  • 엉뚱한 팀 프로젝트가 바뀜 → OAuth 때 팀·프로젝트 잘못 선택
  • 환경변수 등록 실패 → npx vercel login 미실행
  • 서버 목록에 안 뜸 → claude mcp add 후 재시작 안 함
  • "했습니다"인데 실제로는 안 됨 → 결과 확인 없이 넘어감
